# 🗺️《神界：原罪 2》终极版全内容路线攻略

本项目整理 **Divinity: Original Sin 2 — Definitive Edition** 的可跟玩式中文攻略。

它不是简单的任务百科，而是一套按以下层级组织的完整路线：

> **章节 → 自然探索区域 → 推荐等级 → 区域内实际路线 → 每个任务 / 事件的详细操作**

默认路线优先保留 NPC、起源角色剧情、后续任务和正常玩法奖励；如果“剧情最完整路线”与“最大经验路线”不同，会分别说明，并默认推荐前者。

## 📁 项目结构

```text
sin/
├── README.md                 # 项目说明、攻略规范与维护流程
├── md/                       # Markdown 攻略源文件
│   ├── 神界原罪2-全章节详尽攻略索引.md
│   └── 各章节攻略.md
├── html/                     # 由脚本生成的离线增强版网页
│   ├── 神界原罪2-全章节详尽攻略索引.html
│   └── 各章节攻略-增强版.html
└── script/
    ├── build_guides.py       # Markdown → 增强版 HTML
    └── validate_guides.py    # 链接、锚点与文件结构校验
```

Markdown 是内容源，HTML 是阅读版产物。一般情况下只编辑 `md/` 和 `script/build_guides.py`，不要直接修改生成后的增强版 HTML。

## 🚀 使用方法

在项目根目录执行：

```bash
python3 script/build_guides.py
python3 script/validate_guides.py
```

构建脚本会读取 `md/` 中已配置的章节，并把增强版网页写入 `html/`。网页不依赖外部框架，可以离线打开。

## 🎯 攻略目标与默认优先级

攻略应尽量做到：

- 不遗漏正式任务、非日志事件及有价值的隐藏互动；
- 等级曲线自然，不把越级硬打当作默认解法；
- 避免提前触发剧情、错误交付证物或击杀共享 NPC；
- 保留尽可能多的 NPC、剧情、商店、起源角色内容和后续任务；
- 正常玩法下取得尽可能完整的经验、唯一装备、永久增益和跨章奖励；
- 不把刷经验、屠城、偷袭中立 NPC 或任务 Flag Bug 当作常规路线。

出现收益冲突时，默认优先级为：

> **剧情完整度 > 后续内容 > 唯一奖励 > 正常经验 > 金币**

故意击杀 NPC、卡任务状态或利用版本漏洞得到的额外经验，只能放在“最大经验 / 特殊玩法”小节，不能混入默认推荐路线。

## 🧭 章节与区域写作模板

每章开头先给完整的区域路线图与推荐等级曲线。不要直接堆叠几十个任务名称。

每个自然探索区域必须先给“区域卡”：

| 必填项目 | 写作要求 |
|---|---|
| 推荐进入等级 | 给出正常路线下的进入等级；可以提前探索时应说明风险 |
| 推荐完成等级 | 说明清区后的通常等级区间 |
| 主要任务 | 包含主线、支线和重要跨区任务 |
| 非日志内容 | 隐藏对话、鬼魂、动物、商店、宝藏与经验事件 |
| 主要战斗难度 | 指出控制点、地形威胁和常见翻车原因 |
| 不可逆剧情点 | 明确 NPC 生死、任务锁定、物品消失或地图关闭 |
| 建议暂时跳过 | 列出当前等级不适合处理的敌人、Boss 或交付动作 |

区域正文必须是一条真正能照着玩的路线，例如：

> **进入区域 → 接 A → 顺路完成 B → C 只拿线索 → 暂时不要杀 D → 取得灵视后回查 E → 达到目标等级再处理 D → 统一交付任务**

实际步骤应回答：

1. 从哪个传送点或入口进入；
2. 第一站找谁，对话如何选择；
3. 哪个任务只接不做，哪个 NPC 暂时不能杀；
4. 哪些尸体、书信、箱子、钥匙和证物必须搜；
5. 哪些地点需要 Spirit Vision、Pet Pal、Corpse Eater 或特定标签；
6. 哪些隐藏点需要 Wits、Persuasion、Thievery 或 Loremaster；
7. 当前步骤为什么放在这里，提前或延后会错过什么；
8. 哪些任务应在区域末尾统一交付。

每章还应在正式路线前提供两个集中速查区：

- **重要 NPC / 商人速查**：位置、关联任务、是否会移动 / 死亡 / 敌对、正确对话顺序和跨章价值；
- **技能书购买点**：各战斗学派对应商人、条件商人、唯一商品、库存刷新等级和离场前采购节点。

速查表不能代替实际路线；区域正文仍应在玩家经过该 NPC 时再次提醒“先交易、先对话、暂时不要杀或稍后回购”。

## 🧩 “全内容”的收录口径

任务日志不是全部内容。每个区域都应检查：

- 正式主线、支线、小任务、跨章任务及互斥任务；
- 不进入日志但提供经验、奖励、商店、线索或剧情的事件；
- Unique Equipment、套装部件和 Relics of Rivellon；
- 永久属性、Talent、技能、标签、Idol 与特殊状态；
- Ifan、Lohse、Sebille、Red Prince、Beast、Fane 的专属内容；
- Pet Pal 动物对话、Spirit Vision 鬼魂和精灵吃尸体内容；
- 当前看似无用、后续章节才生效的钥匙、书信、卷轴与套装部件；
- 隐藏宝箱、重要尸体、特殊商店、宝藏提示和回访事件。

正常情况下互斥的任务或奖励必须明确写明：

> **这两个结果正常玩法下不能同时取得，不属于遗漏。**

## 🧪 发布前内容审计

每章定稿前必须先建立“内容基线”，再检查正文是否已经把内容放进实际路线。不能只凭目录看起来很长就判断完整。

### 1. 正式任务基线

1. 选一个结构化任务数据库作为主清单，记录该章节的任务总数与英文任务名；
2. 与最新版完整流程、游戏 Wiki 再交叉核对一次；
3. 给每个任务标记：`正文位置 / Checklist 位置 / 条件 / 是否互斥 / 是否跨章`；
4. 前章生死、起源角色或标签造成的条件任务也必须列出，并明确正常周目能否同时出现；
5. 不进入当前章节任务组、但会在本章推进的跨章任务单独统计，不能因为不在主清单里而删除。

推荐在章节开头写清口径，例如：

> 本章任务数据库基线为 69 条；其中 A 与 B 由前章状态决定并正常互斥。跨章任务 C、D 另行纳入，不受该数字限制。

### 2. 八类专项扫描

正式任务核对完成后，再分别扫描以下内容；任何一类都不能用“任务全了”代替：

| 审计类目 | 必查内容 | 正文落点 |
|---|---|---|
| 非日志事件 | 隐藏对话、商店解锁、藏宝提示、无日志经验事件 | 玩家第一次经过时 |
| NPC / 商人 | 初见位置、技能学派、唯一商品、刷新点、死亡 / 离场条件 | 章前速查 + 实际路线 |
| 唯一装备 | 固定摆放、商店、尸体、隐藏箱、战斗中才可偷取、分支独占 | 实际取得步骤 + 区域 Checklist |
| 永久收益 | 属性、Talent、技能、Idol、特殊状态、Source 能力 | 选择发生前，并写明不可逆 |
| 起源角色 | 六名角色的专属对白、共享 NPC 顺序、条件战斗 | 进入共享场景前 |
| 特殊感知 | Pet Pal、Spirit Vision、Elf / Corpse Eater、Scholar 等 | 对应动物、鬼魂、尸体或书前 |
| 长线内容 | 四遗物、跨章钥匙、卷轴、套装部件、可招募 NPC | 拿到当下 + 离章总表 |
| 隐藏探索 | Wits 土堆、密室、传送 / 位移支路、环境机关 | 与地图路线相邻的步骤 |

### 3. 唯一装备审计规则

- 优先使用 Definitive Edition 的物品表与新版流程确认名称、等级、位置和属性；
- Classic 与 Definitive Edition 名称不同，要在同一条目中注明，例如“DE 名称 / Classic 旧称”；
- 任务奖励、商人购买、偷窃、击杀掉落和隐藏箱必须区分，不能笼统写“附近获得”；
- 战斗结束会消失的 NPC / 物品，应在开战前标记【先存档】并写明战斗中取得方法；
- 与保留 NPC、永久奖励或后续商店互斥的装备，必须列成结果对比，不进入默认 Checklist 的“必须取得”口径；
- 只有旧社区清单记录、Definitive Edition 无可靠复核的物品，标为“版本敏感”，不得把旧版属性写成确定事实。

### 4. 路线接入检查

每个已确认内容至少要满足两项：

- 在玩家实际经过的步骤中说明“在哪里、怎么拿、何时拿”；
- 在对应区域 Checklist 中可以勾选；
- 若是互斥分支，在分支表或结果说明中解释为何正常拿不到；
- 若是跨区回访，在章前回访线和最终扫尾中再次出现。

单独堆一张“物品大全”而正文没有取得路径，不算完成；正文写过但离区检查表无法核对，也应视为可读性缺陷。

## ⚖️ 分支写法

分支不能只写“A 或 B 都可以”。每条路线至少说明：

- 谁存活、谁死亡；
- 任务与经验结算；
- 装备、金币和永久奖励；
- 后续剧情与跨章影响；
- 是否锁定其他任务或商店；
- 推荐路线及推荐理由。

如果精确 XP 会因版本、等级、击杀方式或任务状态不同，应描述相对收益并注明差异，不要编造固定数字。

## 🎲 属性、技能与标签门槛

优先写具体条件：

- `【Persuasion 3】`
- `【Thievery 4】`
- `【Wits：建议 18–20+】`
- `【需要 Scholar 标签】`
- `【需要 Pet Pal】`
- `【需要 Spirit Vision】`
- `【推荐 Lv11】`

如果不存在可靠的固定阈值，应写明它会受属性差、对话选项、难度或版本影响，并提供经交叉核对的安全建议值和存档提醒。

## 🏷️ 统一内容标签

Markdown 与 HTML 统一使用以下标签：

`【必做】`　`【容易漏】`　`【永久奖励】`　`【唯一装备】`　`【跨章物品：不要卖】`

`【Pet Pal】`　`【Spirit Vision】`　`【Elf / Corpse Eater】`　`【起源角色专属】`

`【先存档】`　`【暂时不要杀】`　`【暂时不要交任务】`　`【会锁任务】`　`【不可逆】`　`【等级较高，稍后回来】`

增强版 HTML 会把这些标签转换成不同颜色的胶囊标记；Markdown 中仍保留可搜索的原始文字。

## 🎨 Emoji 与阅读界面规范

Emoji 用于建立视觉层级，不应随机装饰或在同一标题中堆叠多个图标。

建议语义：

| Emoji | 含义 | Emoji | 含义 |
|---|---|---|---|
| 🗺️ / 🧭 | 区域图、推荐路线 | 🎛️ | 区域卡 |
| 🏖️ / 🏘️ / 🪦 | 自然探索区域 | 🗿 | 传送点或地标 |
| 💬 / 🕊️ | 对话与和平路线 | ⚔️ / 🔥 | 战斗与高危遭遇 |
| 🕵️ / 🔍 | 隐藏事件与调查 | 👻 | Spirit Vision |
| 🐾 / 🐔 / 🦈 | Pet Pal 或动物内容 | 🧝 | Elf / Corpse Eater |
| 🎁 / 🗡️ | 唯一装备与奖励 | ⭐ | 永久收益 |
| ⚖️ | 分支比较 | ⚠️ / ❌ | 风险、误区与不可逆点 |
| 📋 / ✅ | 结算状态与 Checklist | 📚 | 来源与核对说明 |

所有 Markdown 标题可以直接带语义 Emoji。构建脚本会识别标题开头的图标，并复用到 HTML 目录和标题中，不会重复渲染。

## ✅ 区域与章节检查表

每个区域末尾必须有简短 Checklist，并注明正常情况下的等级：

```markdown
### ✅ 区域离开前 Checklist

- [ ] 关键任务已按推荐分支完成
- [ ] 唯一装备已取得
- [ ] Spirit Vision / Pet Pal / Elf 内容已检查
- [ ] 起源角色专属对话已触发
- [ ] 跨章物品仍在背包或安全储存

> 完成本区主要内容后通常约 Lv10；若明显偏低，优先检查上面的遗漏项。
```

每章最后另设“本章最终不可回头检查”，覆盖未完成任务、起源剧情、唯一装备、四遗物、永久属性、商人、跨章物品、隐藏区域和会随离图消失的 NPC。

## 🔎 资料准确性规范

具体 XP、属性门槛、装备属性、NPC 生死、任务 Flag、奖励与 Definitive Edition 差异不能只凭记忆。

建议交叉核对：

1. 游戏 Wiki、Wiki.gg、Fextralife；
2. GameFAQs 完整流程；
3. Guides4Gamers 任务数据库；
4. Larian 官方论坛；
5. Steam、Reddit 与玩家实测。

社区资料冲突时应明确标注争议、版本与安全做法，不应假装存在唯一确定答案。默认版本始终是 **Definitive Edition**，并纳入 Relics of Rivellon 内容。

推荐的证据规则：

- 任务阶段与条件：优先结构化任务数据库，再用最新版完整流程核对实际顺序；
- 装备名称、属性与位置：优先 Definitive Edition 物品表和新版流程；
- 固定门槛、NPC 生死、Flag 与跨章影响：至少两个独立来源一致，或一个结构化来源加游戏内可验证证据；
- 社区实测只用于补充隐藏机制、平台差异与争议，不单独支撑固定数值；
- 来源冲突时写出冲突点，并给“最安全操作”，不要为了文字简洁擅自选一个答案。

## 🌐 章节撰写的联网研究要求

重新整理任何章节时，现有 Markdown 只能帮助确认文件范围和玩家已经习惯的称呼，**不能充当事实来源**。每次都必须重新联网建立内容基线，再写正文。

最低研究组合：

1. **结构化任务数据库**：建立该章正式任务总数、英文名、条件任务和正常互斥关系；
2. **近期维护的完整流程**：核对实际进入顺序、NPC 对话先后、机关、战斗与回访节点；
3. **Definitive Edition 物品表 / 地图**：核对唯一装备、固定位置、商人、Relics of Rivellon 和版本名称；
4. **Wiki、官方论坛或社区实测**：只用于补充门槛、Flag、平台差异、隐藏事件与存在争议的机制。

每章至少保留三类可点击来源，并在资料说明中写清默认版本。搜索结果摘要只能用于发现线索；凡涉及 NPC 生死、固定数值、任务锁定和唯一装备位置，都应打开原页面核对上下文。

### 🔁 任务名反向覆盖检查

完成正文后，不是从正文向外数“写了多少任务”，而是从任务数据库逐个英文名反查成品：

| 状态 | 合格标准 |
|---|---|
| 正文覆盖 | 能找到实际进入点、操作步骤与结算位置 |
| Checklist 覆盖 | 离开对应区域前可直接勾选 |
| 条件任务 | 写明前章生死、Origin、标签或阵营条件 |
| 正常互斥 | 明确不能同时完成，不算遗漏 |
| 跨章任务 | 不受本章数据库总数限制，单独列入 |
| 非日志事件 | 标为非日志，并写明奖励、剧情或商店价值 |

如果出现“正文提到但章前任务索引没有”或“任务索引列出但正文没有可执行步骤”，章节均不能发布。

## 🤝 分章协作规则

大型全项目更新可以按章节并行，但必须遵守文件所有权边界：

- 每个协作者只编辑分配到的 Markdown，不同时修改共享脚本、README、索引或生成 HTML；
- 每个章节都独立完成联网检索，不能把另一章的来源或旧文件当作核对完成；
- 交付时报告正式任务基线、主要来源、关键补漏和文件行数；
- 共享的构建配置、索引、README、HTML 生成和最终校验由一个维护者统一处理；
- 合并后再做一次跨章道具、起源角色、不可回头节点与相邻章节链接检查。

最终攻略正文只写玩家需要的成品内容，不记录协作过程、修改过程、临时判断或版本讨论聊天。资料争议本身会影响玩家操作时，才以“版本差异 / 安全做法”形式保留。

## 🔧 章节维护与发布流程

1. 重新联网搜索，建立该章正式任务基线并记录来源；
2. 完成八类专项扫描，以及唯一装备 / 商人 / 技能书独立清单；
3. 划分自然探索区域和等级曲线，再把任务、事件与物品接入实际路线；
4. 在 `md/` 新建或完整整理攻略文件；
5. 从任务数据库逐个英文名反查正文与 Checklist；
6. 检查每个区域卡、分支结果、回访点、Origin 顺序和本章最终不可回头检查；
